# en-translator

한국어 소스 문서를 영어로 번역하여 타겟 문서에 기록합니다.

## Usage

```
/en-translator <source> [target] [--review]
```

- `source` — 한국어 소스 파일 경로 (필수). content/ko/ 하위 파일이어야 함
- `target` — 영어 타겟 파일 경로 (선택). 생략 시 `content/ko/` → `content/en/` 자동 매핑
- `--review` — 파일에 쓰지 않고 번역 결과를 출력만 함. 기존 타겟이 있으면 변경점을 표시, 없으면 전체 번역문을 미리보기로 출력

## 실행 전 검증

1. 소스 파일이 존재하는지 확인. 없으면 에러 메시지 출력 후 중단
2. 소스 파일이 `content/ko/` 하위인지 확인. 아니면 에러 메시지 출력 후 중단
3. 타겟 경로가 지정되지 않은 경우 소스 경로의 `content/ko/`를 `content/en/`으로 치환하여 타겟 경로 결정

## 번역 원칙 (반드시 준수)

### 1. 미국 문화권 전달력

미국 문화권에서 분명하고 자연스럽게 읽히는 professional English를 사용한다. colloquial하거나 과도하게 casual한 표현은 피한다. 한국 고유의 개념(예: 기업부설연구소, 마이데이터, 금융감독원)은 미국 독자가 맥락을 이해할 수 있도록 적절한 영어 표현으로 번역하되, 고유명사는 원문 그대로 유지할 수 있다.

### 2. 원문 포맷 엄밀 보존

마크다운 구조를 1:1로 유지한다:
- 헤더 레벨(h1~h6) 동일하게 유지
- 테이블 행/열 수 동일
- 리스트 구조(ul/ol, 중첩 포함) 동일
- HTML 태그 구조 동일 (태그 자체는 보존, 태그 내 한국어 텍스트와 aria-label/alt 등 속성값은 번역)
- `<br>`, `&nbsp;`, `<u>`, `<div>` 등 인라인 HTML 그대로 유지
- 줄바꿈 패턴 동일 (원문이 `<br>`로 줄바꿈하면 번역문도 동일하게)

### 3. Front matter 처리

- `title`, `description` — 번역
- 그 외 모든 키 (`date`, `layout`, `pdf`, `draft`, `tags` 등) — 원문 그대로 유지
- 알 수 없는 새 키가 있을 경우 기본적으로 번역하지 않음

### 4. 의역 및 누락 금지

- 원문의 모든 문장이 영문에 반드시 존재해야 한다
- 심한 의역 금지. 원문의 뜻과 뉘앙스를 충실히 전달
- 표현을 빼놓거나 요약하지 않는다
- 원문에 없는 내용을 추가하지 않는다

### 5. 문서 성격에 맞는 톤

문서의 성격을 파악하여 적절한 톤을 적용한다:
- 이력서/About 페이지 → professional resume 톤 (간결, 성과 중심, action verb)
- 블로그 글 → editorial 톤 (자연스러운 문장, 독자 친화적)
- 프로젝트 소개 → technical writing 톤 (명확, 구체적)

## 실행 단계

1. **소스 파일 읽기** — Read 도구로 소스 파일 전체를 읽는다
2. **번역 수행** — 위 5개 원칙을 적용하여 전체 문서를 영어로 번역한다
3. **결과 출력/저장**
   - 기본 모드: Write 도구로 타겟 파일에 번역 결과를 저장한다. 타겟 파일이 이미 존재하면 덮어쓴다
   - `--review` 모드: 타겟 파일이 존재하면 기존 내용과 번역 결과의 차이점을 텍스트로 표시. 존재하지 않으면 전체 번역문을 출력. 파일은 수정하지 않는다
4. **검증 체크리스트 실행** — 번역 완료 후 아래 항목을 자체 검증한다

## 검증 체크리스트

번역 완료 후 다음을 확인하고 결과를 보고한다:

- [ ] 모든 헤더 레벨(h1~h6)이 원문과 동일하게 보존되었는가
- [ ] front matter의 비번역 키(date, layout, pdf 등)가 변경되지 않았는가
- [ ] 원문의 모든 문장이 영문에 존재하는가 (누락 없음)
- [ ] 본문에 한국어 문자가 남아있지 않은가 (고유명사 제외)
- [ ] 테이블 행/열 수가 원문과 동일한가
- [ ] HTML 태그 구조가 원문과 동일한가
